# Архитектура проекта Airfy

## Обзор

Airfy — это клиентское приложение для прогноза погоды, построенное с использованием **Vue.js 3** и **Vite**. Приложение следует модульной архитектуре, которая разделяет логику на несколько слоев: представление (UI), управление состоянием, работа с API и бизнес-логика.

## Архитектурные слои

### 1. Слой представления (UI Layer) — `components/`

**Назначение**: Визуальное представление информации о погоде.

**Компоненты:**
- **CurrentForecast.vue** — отображает текущую погоду и температуру
- **CurrentForecastDetails.vue** — детальная информация о текущей погоде (влажность, давление, видимость)
- **DailyCard.vue** — карточка с ежедневным прогнозом
- **HourlyCard.vue** — карточка с почасовым прогнозом
- **Header.vue** — заголовок приложения с выбором города и языка
- **Footer.vue** — подвал приложения
- **LoadingScreen.vue** — экран загрузки с прогрессом
- **SimpleDynamicBackground.vue** — динамический фон на Three.js

### 2. Слой управления состоянием (State Management) — `store/`

**Назначение**: Централизованное управление состоянием приложения с использованием **Pinia**.

**Хранилища:**

#### `userStore.js`
Хранит данные о пользователе:
- `userPos` — координаты (широта и долгота)
- `city` — выбранный город
- `language` — выбранный язык
- `requestTime` — время последнего запроса

#### `Serverstore.js`
Хранит метеорологические данные:
- `units` — единицы измерения (°C, hPa, м/с)
- `current` — текущая температура и код погоды
- `daily` — массив ежедневных прогнозов (7 дней)
- `lastFetched` — время последней загрузки данных

**Плагины:**
- **pinia-plugin-persistedstate** — автоматически сохраняет и восстанавливает состояние из localStorage

### 3. Слой работы с API — `api/`

**Назначение**: Запросы к внешним API и обработка ошибок.

**Модули:**

#### `apiForecast.js`
- Получает данные прогноза с Open-Meteo API
- Реализует кэширование на 10 минут
- Трансформирует данные перед сохранением в хранилище

#### `apiLocation.js`
- Работает с геолокацией
- Преобразует координаты в названия городов

#### `apiBrowser.js`
- Использует геолокацию браузера (`navigator.geolocation`)
- Получает координаты пользователя
- Добавляет случайное смещение для приватности

### 4. Слой бизнес-логики — `services/`

**Назначение**: Трансформация, валидация и управление данными.

**Модули:**

#### `DataService.js`
- Получает координаты пользователя
- Преобразует сырые данные API в модели для UI
- Управляет кэшированием
- Координирует загрузку данных между API и хранилищем

#### `Convert.js`
- Конвертирует единицы измерения (Цельсий/Фаренгейт, м/с в км/ч и т.д.)
- Форматирует даты и время
- Интерпретирует коды погоды

#### `offcetGeo.js`
- Утилиты для работы с геолокацией
- Генерирует случайное смещение координат для приватности

## Жизненный цикл приложения

1. **Инициализация** (App.vue `created()`)
   - Инициализируется Pinia с плагином persistedstate
   - Загружается сохраненная тема из localStorage

2. **Запрос геолокации** (App.vue `mounted()`)
   - Приложение запрашивает разрешение на доступ к местоположению
   - Используется `navigator.geolocation.getCurrentPosition()`
   - Координаты добавляются в userStore

3. **Загрузка прогноза** 
   - Вызывается `apiForecast.fetchForecast()`
   - Проверяется кэш (10-минутный timeout)
   - При необходимости запрашиваются данные с Open-Meteo API
   - Данные трансформируются в `DataService`
   - Сохраняются в `Serverstore`

4. **Отрисовка компонентов**
   - Vue реактивно обновляет компоненты при изменении состояния
   - Данные из `Serverstore` отображаются в UI

5. **Кэширование** (persistedstate)
   - При каждом изменении состояния автоматически сохраняется в localStorage
   - При перезагрузке состояние восстанавливается из localStorage

## Логирование и отладка

Все ключевые операции логируются с префиксами для удобства отладки:

- `[APP]` — события приложения
- `[API]` — запросы и ответы API
- `[STORE]` — операции с хранилищем состояния
- `[DS]` — операции DataService

**Пример:**
```
[APP] Загружаем тему из localStorage: dark
[API] Позиция пользователя получена: 55.7558, 37.6173
[API] Обновляем данные с сервера
[DS] Модель ежедневных данных собрана!
[STORE] Данные daily обновлены: Array(7)
```

## Ключевые особенности архитектуры

✅ **Модульность** — каждый слой имеет четкую ответственность  
✅ **Реактивность** — Vue 3 и Pinia обеспечивают автоматическое обновление UI  
✅ **Кэширование** — данные сохраняются локально для экономии трафика  
✅ **Приватность** — координаты пользователя дополняются смещением  
✅ **Масштабируемость** — легко добавить новые компоненты и функции  
✅ **Отладка** — подробное логирование всех операций
